# 🤖 ИИ-Агент: Аналитик 80/20 (YouTube, Видео & Статьи / Telegram Bot)

Этот проект представляет собой мощного автоматизированного ИИ-агента, который принимает любые ссылки в Telegram:
1. **Видеоролики**: Скачивает аудио с YouTube, Shorts, Instagram Reels, TikTok, Vimeo, VK Video, RuTube, Facebook, Twitter/X, загружает в облако и анализирует речь с помощью нейросети Google Gemini.
2. **Статьи и Новости**: Скрапит текстовое содержимое с любых веб-сайтов (используя библиотеки `trafilatura` и `BeautifulSoup4`).
После анализа бот присылает готовую текстовую выжимку по принципу Парето (80/20) вместе с сгенерированной голосовой озвучкой (TTS).

---

## 🚀 Основной функционал (Pipeline)

Проект работает как конвейер, состоящий из следующих этапов:
1. **🔗 Автоматическое распознавание ссылки**: Бот определяет домен ссылки:
   - Если ссылка относится к списку видео-ресурсов (YouTube, Reels, TikTok, Vimeo и др.), запускается **видео-конвейер**.
   - Если это любая другая ссылка (блог, новостной сайт, Википедия), запускается **статейный конвейер**.
2. **📥 Получение контента**:
   - *Для видео:* `yt-dlp` скачивает только аудиопоток в формате MP3.
   - *Для статей:* `trafilatura` (или BeautifulSoup4 в режиме fallback) извлекает чистый текст страницы, отсекая навигацию, рекламу и футеры.
3. **🤖 Аналитика 80/20**: Текст или аудио передаются в Google Gemini API (модели 2.5 Pro/Flash). ИИ анализирует материал по специальному системному промпту `PROMPT_80_20`, убирая 80% воды и оставляя 20% самой ценной сути.
4. **🎙️ Озвучка (TTS)**: Текст выжимки озвучивается через бесплатный `edge-tts` (в `secondmain.py`) или напрямую через облачный Gemini TTS (в `duplicatmain.py`).
5. **📱 Доставка**: Бот отправляет текстовый отчет 80/20 и аудиофайл выжимки пользователю.

## 🛠 Установка и настройка

### 1. Системные требования
- **Python 3.10+** (или выше)
- **FFmpeg** (системный пакет, необходим для обработки аудио в Whisper и yt-dlp)
- Установленный **Docker** (если планируется запуск в контейнере)

### 2. Клонирование и установка зависимостей
```bash
git clone <url_вашего_репозитория>
cd ai_agent
python3 -m venv .venv
source .venv/bin/activate  # Для Linux/macOS
# или .venv\Scripts\activate для Windows
pip install -r requirements.txt
```

### 3. Настройка переменных окружения
В проекте предусмотрен шаблон настроек:
1. Скопируйте файл `.env.example` и переименуйте его в `.env`.
2. Вставьте свои реальные ключи в `.env`:
   - `GEMINI_API_KEY`: Получить в [Google AI Studio](https://aistudio.google.com/).
   - `TELEGRAM_TOKEN`: Получить у [@BotFather](https://t.me/BotFather) в Telegram.

### Запуск Telegram-бота
Бот будет слушать входящие сообщения. Просто отправьте ему ссылку на YouTube:

## 📂 Структура проекта

* `main.py` — Классический файл Telegram-бота с полным циклом обработки (использует локальный Whisper для перевода в текст).
* `secondmain.py` — **Новый** Telegram-бот: сверхлегкая версия, которая отправляет MP3-аудио напрямую в облако Gemini (полностью исключая тяжелый Whisper).
* `duplicatmain.py` — Экспериментальный Telegram-бот: клон `secondmain.py`, в котором `edge-tts` заменен на генерацию аудио напрямую через модель Gemini 2.5 Flash (TTS).
* `localmain.py` — Консольная версия скрипта для пакетной обработки массива ссылок.
* `script_a_audio.py` — Отдельный скрипт: прямой анализ аудио через облачный API Gemini без использования STT.
* `script_b_subtitles.py` — Отдельный ультра-быстрый скрипт: мгновенно вытягивает субтитры через `youtube-transcript-api` и отдает их ИИ (вообще не качает медиа).
* `download.py`, `transcribe.py`, `summarize.py` — Вспомогательные/устаревшие модули.
* `build.sh`, `start.sh`, `delete.sh` — Bash-скрипты автоматизации для Docker и очистки кэша.

### Экспериментальная поддержка Gemini TTS (`duplicatmain.py`)
Был создан новый экспериментальный скрипт `duplicatmain.py` (точная копия `secondmain.py`):
1. **Переход на Gemini TTS:** Библиотека озвучки `edge-tts` заменена на штатную генерацию аудио средствами Google GenAI SDK.

### Глубокая диагностика и исправление ошибок (`secondmain.py`)
Был проведен глубокий аудит кода и исправлен ряд критических уязвимостей и багов:
1. **Утечка локальных аудиофайлов:** Исправлена логика удаления локальных тяжелых `.mp3` файлов. Теперь они гарантированно удаляются в блоке `finally`, исключая засорение жесткого диска при падениях на промежуточных этапах.
2. **Ошибки состояний Gemini API:** Добавлена проверка статуса `FAILED` (прерывание при ошибке на стороне серверов Gemini) — устранена проблема бесконечного ожидания в цикле `PROCESSING`.
3. **Безопасность файловой системы:** Введено жесткое ограничение (100 символов) на длину переменной `clean_title` во избежание `OSError: File name too long` при сохранении видео с чрезмерно длинными названиями.
4. **Необработанные пустые ответы API:** Добавлена проверка `if not response.text`, предотвращающая скрытые падения скрипта при срабатывании фильтров безопасности Google (Safety Settings).
5. **Обработка сбоев озвучки (TTS):** Внедрена строгая проверка кода возврата утилиты `edge-tts`. Бот больше не пытается отправить пользователю несуществующий аудиофайл при сбоях генерации голоса.
6. **Исправление некорректных блоков try-except:** Голые `except:` заменены на `except Exception:`, чтобы не блокировать системные вызовы.
7. **Безопасность инициализации переменных:** Опасные проверки `locals()` в блоках `finally` заменены на безопасную пре-инициализацию переменных (`uploaded_file = None`), что исключает ошибки вида UnboundLocalError.
8. **Устранение излишних импортов:** Убран дублирующийся `import re` внутри внутреннего цикла обработки исключений.
9. **Настройка `yt-dlp` для обхода блокировок YouTube:**
    * Установлен пакет `yt-dlp-ejs` в `requirements.txt` для успешного решения JavaScript `n-challenge` с помощью Node.js.
    * Выполнена замена проблемных клиентов (`tv`, `web_creator`), требовавших авторизации Google (PO Token), на клиент `web`, который поддерживает cookies и корректно решает `n-challenge`.
    * Добавлен параметр `'js_runtimes': {'node': {'path': '/usr/bin/node'}}` (в виде словаря) для явного и корректного указания интерпретатора через Python API yt-dlp.
    * Удален `player_skip: ['configs', 'webpage']`, который блокировал получение параметров шифрования.
10. **Исправление ошибки кодировки ASCII при загрузке в Gemini API (`UnicodeEncodeError`)**:
    * Библиотека `httpx` (внутри `google-genai`) падала при отправке файлов, содержащих кириллицу или спецсимволы в названии (например, `Как_ПРАВИЛЬНО...mp3`).
    * Переработана архитектура файлов: локально все временные аудио и текстовые файлы теперь сохраняются под безопасными уникальными именами (`file_id` на основе timestamp). Это полностью исключило конфликты HTTP-парсеров.
    * При этом сохранен высокий уровень UX: при отправке готовых выжимок в Telegram бот динамически возвращает им оригинальные, читаемые названия с помощью параметра `filename` в `FSInputFile`.
11. **Динамическое отображение прогресса (UX + Логирование)**:
    * В `yt-dlp` внедрен `progress_hooks`, который позволяет отслеживать процент скачивания длинных аудиофайлов в реальном времени.
    * Переработан цикл `PROCESSING` при ожидании ответа от Google Gemini: добавлен вывод времени обработки.
    * Теперь бот обновляет сообщение в Telegram (и логи на сервере) каждые 3-4 секунды, показывая процент скачивания (`Скачиваю аудио: 45.2%`) и секундомер обработки облака (`Облако обрабатывает файл... (12 сек)`), что защищает от эффекта "зависшего бота" без риска получить бан от API Telegram за флуд (FloodControl).
